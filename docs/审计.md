## BLE 换机诊断（2026-08-05）

- 最新现场复核：目标端显示“已连接”时开发板仍为红灯。重启后 45 秒内记录 11 次 `connection failed`、11 次 `encryption failed status=7`、11 次 `disconnect` 和 0 次 `subscribe`；每次失败后固件重新广播。结论是中心设备仍保存并反复尝试旧 LTK，尚未完成一次双方密钥一致的新配对。
- 当前排除项：不是 BLE 未广播，日志持续出现 undirected advertising；不是 LED 状态错误，固件从未进入成功 HID 连接/订阅阶段；不是主机串口无输入造成，因为失败发生在 HID 报告发送之前的安全协商阶段。

- 白名单：未发现；`firmware/main/esp_hid_gap.c:1061-1066` 使用通用、非定向、无限时长广播，没有绑定到本机蓝牙地址。
- 单连接占用：ESP-IDF `components/esp_hid/src/nimble_hidd.c:77-85,590-592` 只维护一个 `connected` 和一个 `conn_id`；固件在断开事件后才重新开始广播。旧设备保持连接或自动重连时，新设备无法同时接入。
- 绑定状态不对称（已修复的根因）：历史配置在 `firmware/main/esp_hid_gap.c` 启用 bonding，却未持久化密钥。现已在 `firmware/sdkconfig.defaults` 和本地 `firmware/sdkconfig` 启用 `CONFIG_BT_NIMBLE_NVS_PERSIST=y`，并由 `firmware/main/ble_output.c` 编译期保护；旧中心设备保存的历史 LTK 仍需删除配对后重新生成。
