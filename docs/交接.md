## 当前 BLE 诊断

+ `artifacts/host-serial-20260823-202445.log:8-160`：USB 启动枚举保护结束后，`bursts_remaining` 从 23 递减到 0，约 30.476 秒后才出现 `connection established`。
+ 同一日志三次断线后的重连耗时约为 176.041 秒、31.048 秒和 31.431 秒；每次先执行 24 轮定向广播，176 秒样本在此后还包含普通广播阶段中心端长期未发起连接。
+ `firmware/main/esp_hid_gap.c:923-933` 会为绑定设备装填 24 轮预算；`1144-1160` 在断线后再次装填；`1354-1381` 使用 `BLE_GAP_CONN_MODE_DIR` 与 `BLE_GAP_DISC_MODE_NON`。因此“绑定设备未响应时约 30 秒才回落普通广播”是当前可确认的直接原因。
+ 三次断线均记录 `reason=531`。该原因发生在已连接之后，随后触发下一轮定向重连；当前证据不支持把本次建连慢归因于加密或连接参数更新。
+ `firmware/main/usb_output_liveness.h:13` 和 `firmware/main/hid_output.c:638-662` 另有一次性 3000 ms USB 冷启动枚举宽限期，这是次要固定延迟。
+ 具体的 Windows 中心端原因仍未验证：当前日志没有定向目标地址、RPA 解析结果或 Windows 扫描/连接状态。

## 特殊指令与边界

- 日常运行使用 `showDeviceLogInUi: false`；完整设备日志只用于短时排障。
- 修改主机后运行 Release Build 和 `dotnet format --verify-no-changes --no-restore`；修改固件后进入 ESP-IDF 环境运行 `idf.py set-target esp32s3` 和 `idf.py build`。
- 停止转发、断线、切换或退出时必须发送 `ReleaseAll`；不要为刷写强制结束 EXE，优先使用本机刷写接口释放 COM。
- 固件刷写接口仅接受本机 Loopback 请求；UDP 全零位移命令应由发送端跳过，接收端拒绝规则不能放宽。
- 不得删除或重置 `D:\ESP32-S3-HID-Bridge-worktrees\input-latency-telemetry`，不得把备份 EXE 或 `artifacts/` 纳入提交。
