## 2026-09-22 透明代理方向确认（待用户补充边界）

### 当前目标

后续正式拓扑改为：鼠标侧板的原生 USB Host 接真实鼠标，鼠标侧板 UART0/CH340 接收软件输入，GPIO17/18/GND 的板间 UART1 将实体原始 USB/HID 通信与软件命令传给电脑侧板；电脑侧板仅通过原生 USB 向接收端电脑严格克隆真实鼠标，并在最终 HID Input Report 中合并软件输入。停止把“严格克隆内隐藏 HID 控制隧道”作为主线。

+ 驱动兼容主线改为不透明透传：动态复制真实 Device/Configuration/String/HID Report 描述符，原样转发 Input/Output/Feature 与可支持的标准、HID class、vendor 控制事务；固件只解析已经证明安全的相对鼠标字段用于叠加。
+ 软件输入入口迁移到鼠标侧 UART0；电脑侧板不新增 CDC、自定义 HID 或私有 Report，避免改变接收端所见的鼠标 USB 拓扑。
+ 软件移动不在鼠标侧直接改写实体 report；鼠标侧将标准化软件命令经独立有界队列送到电脑侧，由电脑侧利用当前动态 report layout/template 完成最终合并。
+ 实体 Input 保持最高优先级；软件 move/release 为高优先级；厂商控制事务使用独立有界队列；Profile、日志和诊断保持低优先级。
+ “尽可能兼容所有厂商”限定为 USB HID 鼠标及其键盘/消费者控制/vendor HID 复合接口，不等同于任意 USB 音频、存储、固件升级或超出 ESP32-S3 Full-Speed/端点预算的设备。
+ 物理拔插必须镜像到接收端：鼠标侧 USB Host 检测到真实设备拔出后，先发送最高优先级 release/device-gone，电脑侧释放所有实体与软件按键并主动断开 USB Device；接收端必须观察到真实 PnP 移除。重新插入时重新采集、传输并校验完整 Profile，之后才重新连接枚举，禁止沿用旧身份或仅停止报告。
