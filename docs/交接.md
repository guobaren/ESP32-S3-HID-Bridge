# 项目交接

更新时间：2026-08-06

## 当前目标

当前版本只启用 Windows 通过 USB-to-UART 或原生 USB CDC 向 ESP32-S3 输入，并由开发板通过 USB HID 或 BLE HID 输出。Wi-Fi 输入、SoftAP 配网和开发板到 Windows Target Agent 的 Wi-Fi 输出实现继续保留，但默认构建和运行入口均关闭。

## 已完成项

+ 主机端支持自动发现 USB-to-UART 与原生 USB CDC，并继续使用同一套串口协议、会话租约和 `ReleaseAll` 安全路径。
+ 固件支持原生 USB `CDC + HID` 复合设备；BLE 加密并可发送后优先作为输出，断开后回退 USB HID。
+ BLE 鼠标移动采用固定 10 ms 节拍发送最新合并位移，并记录协商连接间隔与发送统计。
+ 主机端增加“精简日志（高性能）/完整日志（排障）”下拉框；精简模式减少串口日志解析、磁盘写入和 UI 刷新。
+ Release 构建完成后将 `HidBridge.Host.exe` 复制到项目根目录；当前文件 SHA-256 为 `2ABD8E0F4DF17DC87CC7198B0557E4A22FC10996A7D58BC424171639D1D1E5F9`。
+ 主机端 `transport=wifi` 当前会被功能闸门拒绝；固件统一 Wi-Fi 运行时开关及 Kconfig 默认项均关闭。
+ Wi-Fi 输入、SoftAP 配网、Target Agent 输出代码均已保留并加注释，没有删除未来恢复所需实现。
+ ESP-IDF v6.0.2 固件构建通过，镜像 `firmware/build/esp32_s3_hid_bridge.bin` 的 SHA-256 为 `BB8F3119F201475E08F196F9BDE447414E141A22AA22C94A14F98436E4169DE1`。
+ 主机 Release 构建、检查程序、格式检查和 `git diff --check` 已通过；构建、自动检查与真实设备结果分别记录在 `docs/审计.md`。

## 特殊指令

- 当前真实拓扑：`Windows → USB-to-UART/原生 USB CDC → ESP32-S3 → USB HID/BLE HID → 目标设备`。
- 不要把 Wi-Fi 实现删除；恢复前必须同时审查 `firmware/main/runtime_features.h` 与 `CONFIG_HID_BRIDGE_WIFI_ENABLE`，并重新完成安全和真实链路验收。
- 主机 EXE 编译后应直接更新项目根目录的 `HidBridge.Host.exe`。
- `artifacts/` 只保存本机诊断产物，不得提交。
- 固件构建：进入 `firmware`，加载 `scripts/Enter-EspIdf.ps1` 后运行 `idf.py set-target esp32s3` 与 `idf.py build`。
- 固件烧录：`idf.py -p <实际串口> flash`；烧录前重新确认开发板枚举和 COM 口。
- 主机验证：运行 Release build、Checks build/run 及两个项目的 `dotnet format --verify-no-changes --no-restore`。
- 模拟、单元、构建与真实设备结果必须分开记录，启动成功或退出码为 0 不能替代输出结果核对。
