## 2026-08-11 G HUB 识别边界分析

+ 已确认桥接只转发标准键盘/鼠标输入报告；该分析时的旧固件在被控端枚举为 ESP32-S3 通用 `CDC + HID` 或 HidBridge BLE HID，并非原始罗技鼠标，USB 枚举形态现已由动态 profile 方案取代。
+ USB 当前使用 Espressif VID、默认 PID 和 `Espressif Device` 字符串；BLE 使用 `VID=0x303A/PID=0x4002`、制造商 `HidBridge`，均不具备罗技设备身份。
+ USB HID 的 `GET_REPORT` 返回空、`SET_REPORT` 不处理，且没有罗技厂商专用接口、Feature Report、配置协议及反向控制通道，因此被控端 G HUB 无法发现或配置原鼠标。
+ 若目标是让被控端 G HUB 完整识别，需采用物理 USB 透明切换/转接，使真实鼠标或罗技接收器直接枚举到被控端；仅伪造 VID/PID 不足且不应作为实现路线。

## 2026-08-11 通用键鼠 USB 身份方案

+ 已确认当前 USB HID 本身包含键盘和鼠标两个 Report ID，但配置描述符同时包含 CDC，且设备描述符/字符串仍来自 Espressif 默认配置，因此 Windows 复合设备父节点会暴露 Espressif 身份。
+ 推荐新增目标端 `HID-only` 固件配置：原生 USB 只保留键盘和鼠标 HID，移除 CDC 接口及 `usb_cdc_input_init()`；控制端改用板载 CH340/UART 输入。
+ 显示为中性设备需要提供自定义 Device/String Descriptor，例如制造商 `HID Bridge`、产品 `USB Keyboard Mouse`；这只改变友好名称，不会改变硬件 ID。
+ 若要求硬件 ID 也不出现 Espressif，必须使用自有或合法分配的 VID/PID；不得借用罗技或其他厂商 VID/PID。为最大化 BIOS/系统兼容性，可进一步拆成独立 Boot Keyboard 和 Boot Mouse 两个 HID Interface，而不是共用一个 `HID_ITF_PROTOCOL_NONE` 接口。
