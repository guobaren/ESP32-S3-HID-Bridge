# 项目交接

## 当前目标

- 维护当前 Raw Input 相对移动链路与贝塞尔曲线可行性分析的远程文档状态。

## 已完成

+ 已在 `codex/multi-transport-softap` 分支 `69bf7b2` 上重新核对主机、协议、固件 USB/BLE 输出和 Windows Target Agent 链路。
+ 已确认当前主机逐个处理 Raw Input 相对增量，并立即发送相对鼠标报告；协议不包含绝对起点、终点、持续时间或控制点。
+ 已用 `(300,50)` 位移复算现有按轴限幅行为：当前拆分为 `(127,50)+(127,0)+(46,0)`，总量守恒但中间轨迹偏转。
+ 已确认等比例 DDA 拆分可得到 `(100,17)+(100,16)+(100,17)`，同时保持方向、单帧范围和最终总位移。
+ 已完成结论：大位移拆包偏转应优先使用等比例分段修正；贝塞尔适用于已知终点的自动移动，或接受缓存延迟的轨迹拟合，不适合直接套用到每个实时 Raw Input 增量。
+ 主机 Release 构建及 `dotnet format --verify-no-changes` 已通过。
+ 本次发布范围已确认仅包含 `docs/交接.md` 和 `docs/审计.md`，不包含功能代码。
+ 两份分析文档已提交为 `e59200e` 并推送到 `origin/codex/multi-transport-softap`。

## Next Steps

1. 明确需求是“修复大位移折线偏转”“实时手动防抖”还是“自动移动到目标点”。
2. 若修复当前偏转，在主机端将独立按轴限幅改为带整数余量的等比例 DDA 拆包，并增加位移守恒、方向误差和边界测试。
3. 若需要贝塞尔自动轨迹，增加有界、可取消、按输出节拍发送的主机端轨迹调度器，并在真实 USB/BLE/Windows Agent 链路测量轨迹和延迟。

## 特殊指令

- 串口协议变化时同步更新 `docs/protocol.md`、C# 编码器和 C 解析器。
- 按钮与滚轮事件不得为平滑轨迹而延迟；停止、断线、取消和退出必须清空待发送轨迹并执行 `ReleaseAll`。
- 模拟数值复算不能替代真实 USB、BLE 或 Wi-Fi Target Agent 验证。
