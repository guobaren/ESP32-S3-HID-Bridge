# 发布与版本维护

本文面向维护者，说明本地发布入口和版本号同步规则。普通使用者请按 README 的快速开始和刷写说明操作。

## 版本号

Host 版本号集中在 `host/HidBridge.Host/HidBridge.Host.csproj`，发布时必须同步修改三个字段：

```xml
<Version>0.1.2</Version>
<FileVersion>0.1.2.0</FileVersion>
<AssemblyVersion>0.1.2.0</AssemblyVersion>
```

`一键发布.cmd` 从 `<Version>` 自动生成 `v<Version>` tag，例如 `0.1.2` 对应 `v0.1.2`。因此每次发布都要一起更新这三个字段；GitHub Actions 手动触发的默认 tag 也应与本次版本保持一致。直接调用 `Publish-GitHubRelease.ps1 -Tag ...` 时，显式 tag 必须匹配该版本。已存在的 tag 或 Release 不会被本地发布脚本覆盖。

## PowerShell 入口

仓库保留两个发布件准备入口：

- PowerShell 7：`pwsh -NoProfile -File .\scripts\Prepare-Release.ps1`。
- Windows PowerShell 5.1（系统自带，无需安装 `pwsh`）：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Prepare-Release-PS5.ps1`。

两个入口接受相同的 `-SkipHostBuild` 和 `-BuildFirmware` 开关。PS5.1 入口是薄转发脚本，会把参数交给主实现；`Publish-GitHubRelease.ps1` 根据当前 PowerShell 主版本自动选择入口。`一键发布.cmd` 使用 Windows PowerShell 5.1，因此在未安装 PowerShell 7 的 Windows 上也可运行。

`Prepare-Release.ps1` 生成项目根目录下的 `release/`。`Publish-GitHubRelease.ps1 -Tag v0.1.2 -PackageOnly` 可离线生成 ZIP，不创建或上传 GitHub Release；去掉 `-PackageOnly` 才会执行 GitHub 发布流程。常规 Host Release build 会在构建后更新根目录 `HidBridge.Host.exe`；只做验证且需要保留根 EXE 时，使用 `-p:BuildingRootExecutable=true`。
